所有数字都来自本机实测（AMD RX 9060 XT 16 GB，WSL2 Ubuntu 22.04，ROCm 6.4，torch 2.6）。
`log.csv` 里每一步的 train/val loss 都在，`fit_curve.py` 可以直接重新拟合。

最近 5000 步只降 0.0020（每万步约 0.004），幂律拟合 `L = -0.248 + 7.840·step^-0.050`。

## 2. 采样质量（同参数下的温度敏感性）

固定 5 组提示词 × 8 段（`gen_samples.py` → `out/samples.md`）：

| temperature | 现象 |
|---|---|
| 0.7 | 稳，句子通顺，但保守 |
| **0.75–0.8** | **推荐**：有变化又不飘 |
| 0.9 | 开始绕圈、重复短语 |
| 1.0 | 空提示直接跑题 |

模型会写「网文腔」、会分段和引号对话，但 2–3 句后容易跑题、人名会串。

## 3. SFT（三轮，详见 [sft-guide.md](sft-guide.md)）

数据：25 条手写指令 + 从小说里自动造的 3000 条「续写」样本（回答 token 1.14M）。

| 实验 | 步数 / lr / dropout | train loss | 回答部分 val | 小说 val | 结论 |
|---|---|---|---|---|---|
| base | — | — | 4.1702 | 4.0718 | 只会续写 |
| A | 226 (2 ep) / 1e-4 / 0 | 4.33 → 3.56 | 4.3011 ↑ | 4.2439 ↑ | 过拟合 + 灾难性遗忘 |
| B | 60 / 3e-5 / **0.1** | **8.0 起步** | 4.31 ↑ | — | 事后加 dropout 直接把模型打崩 |
| C | 120 (1 ep) / 3e-5 / 0 | 4.33 → 4.10 | **4.1527 ↓** | 4.0798 | 权重几乎无损，但没学会「回答」 |

关键诊断（`tools/check_damage.py`）：C 在原始小说验证集上 loss 4.0798 ≈ base 4.0718，
**不是权重坏了**，而是 25 条指令被 3000 条续写样本淹没（1:120），模型学到的是
「`助手：` 之后继续写小说」，于是吐 `用户：` 行和乱码 token。贪心/低温解码下小模型还会掉进重复循环。

结论：SFT 管线可用，**瓶颈是数据**——要把指令数据做到几万条、配比 ≥70%，或换更大的底座。
